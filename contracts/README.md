# Contract test vectors

## v3 binary wire format (T30)

`vectors.json` is the single parity suite for the v3 wire format described in
`MESSAGE_SPEC.md`. Each vector carries the typed `body`, its `bodyHex`, the
`unsignedHex` header+body, the derived `msgIdHex`, and the signing actor; the
`keys` object holds fixed test scalars. Two vectors include a static
`signedMessageHex` fixture. ECDSA is randomized, so those fixtures are
verify-only.

- `ref/codec.py` is the reference encoder and decoder.
- `ref/make_vectors.py` regenerates the file.
- Ledger tests: `ledger/tests/test_v3_codec.py`.
- Kotlin codec: `android/app/src/main/java/com/agrichain/relay/V3Codec.kt`
  and `V3Bodies.kt`; parity test `com.agrichain.relay.V3CodecVectorsTest`.

```bash
python3 contracts/ref/codec.py
cd ledger && python3 -m pytest -q tests/test_v3_codec.py
cd android && ./gradlew testDebugUnitTest --tests 'com.agrichain.relay.*'
```

## v2 canonical JSON (T17, frozen)

`event-vectors.json` is the v2 canonical-JSON parity suite for Python and Kotlin.
Each vector is an event-shaped object (the signed fields only) plus the expected
canonical string and SHA-256.

Canonical form:

- UTF-8; keys sorted A–Z at every level; separators `,` and `:`; no whitespace.
- Object keys are ASCII printable (0x20–0x7E). String values may be non-ASCII
  and are emitted as raw UTF-8, never `\uXXXX`.
- Control characters use the standard JSON escapes (`\b`, `\f`, `\n`, `\r`,
  `\t`, otherwise `\u00XX`). `"` and `\` are escaped; `/` and `<>` are not.
- Integers are signed 64-bit. Floats, non-string keys and unpaired surrogates
  are rejected. `hash` and `sig` are excluded from the signed bytes.

```bash
cd ledger && python3 -m pytest -q tests/test_vectors.py
cd android && ./gradlew testDebugUnitTest --tests 'com.agrichain.core.CanonicalVectorsTest'
```

The AndroidKeyStore instrumented leg (`connectedDebugAndroidTest`) needs a
phone and `adb reverse`; it stays pending until a device is attached.

To add a v2 case, append an object to `event-vectors.json` `vectors` with a
unique `name`, the `value`, its `canonical` string and `sha256`. Compute both
from the Python `crypto.canonical_json` / `crypto.sha256_hex` helpers so the
expected bytes are generated by the same implementation the ledger uses.
